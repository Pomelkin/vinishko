# AI-сомелье: микросервис

Асинхронный HTTP API и решение сомелье находятся в едином пакете `app/`. Реализация v2, промпты и экспертная база перенесены из `../vinishko/ai_somelier` (коммит `e114c1ad613d9fbefe207a8eaaa62ec7d531ab49`); импорты и пути к ресурсам адаптированы для пакета `app`. Сервис разворачивается самостоятельно, без доступа к исходному репозиторию. Исходный вызов `respond()` синхронный; API запускает его через `asyncio.to_thread`, поэтому ожидание OpenRouter не блокирует обработку других сессий.

## Запуск через Docker Compose

Если Docker Desktop ещё не установлен, выполните [инструкцию для Windows](docs/DOCKER_WINDOWS.md).

```powershell
Copy-Item secrets/openrouter_api_key.txt.example secrets/openrouter_api_key.txt
notepad secrets/openrouter_api_key.txt
docker compose up --build -d
```

В `secrets/openrouter_api_key.txt` замените пример своим ключом OpenRouter. Файл исключён из Git и Docker build context. Compose монтирует его как `/run/secrets/openrouter_api_key` и передаёт сервису только путь через `OPENROUTER_API_KEY_FILE`; значение ключа не хранится в `compose.yaml` или переменных окружения контейнера. История сессий хранится в постоянном томе `sommelier_sessions`. Сервис слушает `http://127.0.0.1:8000` на хосте.

Для ручной проверки откройте [notebooks/sommelier_api.ipynb](notebooks/sommelier_api.ipynb). Notebook создаёт UUIDv7, открывает диалог, отправляет вопрос, читает историю и при необходимости удаляет сессию. Запуск Jupyter из этого проекта:

```powershell
uv sync
uv run --with jupyterlab --with ipykernel jupyter lab notebooks/sommelier_api.ipynb
```

Для автоматической проверки того же запущенного сервиса по HTTP:

```powershell
uv run python scripts/smoke_api.py
```

Скрипт вызывает реальный API по `http://127.0.0.1:8000`, проверяет первый ответ, следующий вопрос и историю, затем удаляет созданную сессию. Параметр `--base-url` задаёт другой адрес, `--keep` сохраняет сессию. Эта проверка вызывает OpenRouter и расходует токены.

## Запуск без Docker

```powershell
uv sync
$env:OPENROUTER_API_KEY = "..."
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1
```

При локальном запуске можно использовать `OPENROUTER_API_KEY_FILE` с путём к файлу вместо `OPENROUTER_API_KEY`. Если заданы обе переменные, файл имеет приоритет. `SOMMELIER_DATA_DIR` задаёт каталог для JSON-файлов сессий (по умолчанию `./data/sessions` относительно рабочей директории). `OPENROUTER_SITE_URL` и `OPENROUTER_APP_TITLE` передаются в OpenRouter, если заданы. Для сохранения диалогов между развёртываниями каталог сессий нужно разместить на постоянном диске. Сервис рассчитан на **один процесс**: блокировки обращений к сессии действуют внутри процесса.

Интерактивная спецификация доступна на `/docs`, схема OpenAPI — на `/openapi.json`. Снимок схемы для клиента лежит в [docs/openapi.json](docs/openapi.json).

## Контракт v1

`session_id` во всех URL — UUID версии 7, который создаёт и хранит клиент. Он определяет один диалог по одной распознанной карточке вина. Повторное открытие того же идентификатора возвращает `409`. Для другого вина клиент создаёт новую сессию. Сервис не выдаёт идентификаторы и не меняет карточку существующей сессии.

| Метод и путь | Назначение | Успех |
| --- | --- | --- |
| `POST /v1/sessions/{session_id}` | Создать диалог и сразу получить первое сообщение | `201 TurnResponse` |
| `POST /v1/sessions/{session_id}/messages` | Отправить следующий вопрос или выбранную подсказку | `201 TurnResponse` |
| `GET /v1/sessions/{session_id}` | Получить все видимые реплики по порядку | `200 SessionResponse` |
| `DELETE /v1/sessions/{session_id}` | Удалить диалог и файл истории | `204` |
| `GET /health` | Проверить доступность процесса | `200` |

### Открытие диалога

```http
POST /v1/sessions/01993959-0000-7000-8000-000000000001
Content-Type: application/json

{
  "wine": {
    "Название вина": "Кокур",
    "Категория": "Белое",
    "Регион": "Крым",
    "Сорт винограда": "Кокур",
    "Slug": "kokur"
  },
  "candidates": [
    {"Название вина": "Другой кокур", "Slug": "other-kokur"}
  ]
}
```

`wine` — непустая каталожная карточка. `candidates` — обязательный массив из 0–5 карточек в порядке релевантности. Значения полей карточки: строка, число, логическое значение или `null`. Названия используемых полей определены в `PROMPT_CARD_FIELDS` пакета v2; неизвестные поля допускаются, но модель их игнорирует. Пустые значения карточки v2 отображает как «Нет данных». Первое сообщение генерируется без пользовательского текста и содержит **ровно две** подсказки.

```json
{
  "session_id": "01993959-0000-7000-8000-000000000001",
  "message": {
    "role": "assistant",
    "content": "...\nЧем я могу помочь?",
    "suggestions": ["Что во вкусе", "Как подавать"]
  }
}
```

### Следующий вопрос

```http
POST /v1/sessions/01993959-0000-7000-8000-000000000001/messages
Content-Type: application/json

{"content": "Подойдёт к утке?"}
```

`content` после удаления пробелов по краям должен содержать 1–4000 символов. Ответ имеет тот же формат `TurnResponse`, но `suggestions` равен `null`. Клиент не передаёт историю, `wine` или `candidates` повторно. Сервис добавляет вопрос в накопленную историю и передаёт исходные сообщения модели в v2.

`GET` возвращает `{ "session_id": "...", "messages": [...] }`. В `messages` находятся первый ответ сомелье, затем пары «пользователь — сомелье». У пользовательских сообщений `suggestions: null`. Поля провайдера `reasoning` и `reasoning_details` клиенту не отдаются; они сохраняются в JSON сессии для продолжения контекста.

### Ошибки

| Код | Когда |
| --- | --- |
| `404` | Сессия не найдена при чтении, отправке вопроса или удалении |
| `409` | Идентификатор уже занят при открытии |
| `422` | Неверный UUIDv7 или данные запроса; тело ошибки стандартное FastAPI |
| `502` | Ошибка OpenRouter, несоответствие ответа контракту v2 или сбой генерации |
| `503` | Ключ OpenRouter не задан, файл секрета отсутствует, пуст или недоступен |

Для `404`, `409`, `502` и `503` тело имеет вид `{ "detail": "..." }`. Если генерация не удалась, новые реплики не записываются: запрос можно повторить. Запись сессии идёт в отдельный временный файл с последующей атомарной заменой. Обращения к одному UUID сериализуются; разные UUID могут обрабатываться одновременно. Диалоги не удаляются автоматически: клиент вызывает `DELETE` по завершении или владелец сервиса очищает каталог хранения по своей политике.

## Проверка

```powershell
uv run python -m unittest discover -s tests -v
```

Тесты API используют подставной движок и не требуют ключа OpenRouter. Отдельная проверка подготавливает запросы через включённый `app.solution.v2` и читает его промпты и экспертную базу.
