# Распознавание незнакомого вина

Сервис по фото бутылки определяет два признака для дальнейшего поиска похожих вин: категорию (цвет вина) и каноническую винодельню. Товарный `slug` он не угадывает: исходного вина может не быть в каталоге. Если признак определить нельзя или его значения нет среди допустимых, сервис возвращает для этого поля `Не удалось определить`.

Код организован по образцу `vinishko-backend`: HTTP слой в `app/main.py`, обработка результата в `app/service.py`, публичные модели в `app/models.py`, а перенесённое решение в `app/solution/`. Файлы `prompt.txt` и `config.json` скопированы из `../vinishko/candidates/solution/v1` без изменений. `predictor.py` адаптирован для приёма байтов из HTTP запроса и автономной работы. Снимок допустимых значений в `app/kb/catalog_values.json` получен из `../vinishko/data/catalog/catalog.csv` (SHA-256 `9c9980af306cefe6f9608df822c4e61f02ea84b2e97d19fdca26812aa9448774`): 4 категории и 135 виноделен.

## API

`POST /v1/predict` принимает `multipart/form-data` с единственным обязательным полем `image`. Допустимы JPEG, PNG, WebP и GIF до 10 МиБ; формат определяется по сигнатуре файла. При успехе ответ имеет HTTP 200:

```json
{"category": "Красное", "brand": "Фанагория"}
```

Отказ модели по одному или обоим полям тоже считается успешным ответом. Неверный формат изображения даёт 415, размер больше лимита — 413, отсутствие ключа OpenRouter — 503, сбой провайдера или невалидный ответ — 502. Сырой ответ модели и служебная трасса не публикуются. `GET /health` проверяет процесс, документация FastAPI доступна на `/docs`, снимок схемы — в `docs/openapi.json`.

## Локальный запуск

```powershell
uv sync
$env:OPENROUTER_API_KEY = "<ваш ключ>"
uv run uvicorn app.main:app --host 127.0.0.1 --port 8810
```

Для запроса из другого терминала:

```powershell
curl.exe -F "image=@C:\path\to\bottle.jpg" http://127.0.0.1:8810/v1/predict
```

Вместо `OPENROUTER_API_KEY` можно задать `OPENROUTER_API_KEY_FILE` с путём к файлу ключа; файл имеет приоритет. Не добавляйте ключ в Git. Модель, провайдер, параметры генерации и таймаут заданы в `app/solution/config.json` как в исходном решении.

## Docker Compose

Создайте `secrets/openrouter_api_key.txt` с ключом OpenRouter, затем запустите:

```powershell
docker compose up --build -d
```

Compose открывает сервис на `http://127.0.0.1:8810`. Каталог исходного репозитория для запуска не нужен. Проверки без обращения к OpenRouter: `uv run python -m unittest discover -s tests`.

Результат исходного решения на 20 размеченных фото: 19/20 верных категорий, 14/20 верных виноделен, 13/20 верных пар. Эти данные не проверяют товары вне каталога и не гарантируют время ответа менее 3 секунд.
