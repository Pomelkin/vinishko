# Второй уровень: выбор позиции среди кандидатов поиска

Шаг пайплайна после визуального поиска. Вход — только бутылки с кандидатами, `list[BottleCandidates]`; выход — по одному ответу на каждую,
в том же порядке: `MatchedBottle` с ровно одной позицией каталога либо `UnmatchedBottle` с отказом `near_duplicate_not_found`
(`vinishko/pipeline/structs.py`); отказ — `Rejection` с `NearDuplicateReason`, `stage = resolve`. Списки кандидатов шаг не переставляет, он принимает решение.

```python
from vinishko.pipeline.pipeline import Pipeline

result = Pipeline()(
    photo
)  # второй уровень поднимается по умолчанию, resolve=False — без него
result.resolution  # MatchedBottle | UnmatchedBottle на каждый ответ поиска; отказы поиска переходят сюда как есть
result.matched  # только MatchedBottle: .candidate — выбранная позиция, .source — group | final, .checklist — наблюдения модели
```

`Pipeline` сам отдаёт второму уровню только `BottleCandidates` и ставит его ответы на места ответов поиска; `result.items` и `result.crops`
учитывают отказы обоих шагов. Отдельно: `NearDuplicateResolver()(found)`. В `config.yaml` поиска по умолчанию `search.mode: groups`, как нужно этому шагу.

## Как выбирает

Код `configs.py`, `models.py`, `predictor.py` и prompt-файлы `resolve_multiple_same`, `compare_year_*` адаптированы из `ndr/solutions/v5`
исходного репозитория; `resolve_finalists.txt` и два круга — наши; `resolve.py` — адаптер к структурам пайплайна и картинкам в памяти.

Кандидаты бутылки делятся на группы одинакового дизайна в порядке поиска, и выбор идёт в два круга:

1. **Группы.** По каждой группе из нескольких позиций — один запрос к модели (задача `group`, промпт `resolve_multiple_same`): лучшая позиция
   группы либо `not_found`. Позиция без группы, то есть группа из одной, проходит дальше без запроса. Запросы всех групп всех бутылок идут параллельно.
2. **Финал.** Финалисты — выбранные в группах и одиночки, в порядке поиска. Один запрос (задача `final`, промпт `resolve_finalists`) выбирает
   среди них позицию либо `not_found`; с одним финалистом-одиночкой это проверка, поэтому ни один ответ не уходит без модели. Финал не нужен,
   если финалист один и его уже выбрала модель в своей группе (`source = group`); иначе ответ — из финала (`source = final`). Финалистов нет — отказ.

Сколько групп приходит, решает поиск: `top_groups`, `group_threshold` и `group_margin` в его `config.yaml`. Каждая группа нужна целиком, поэтому
**поиск должен идти в режиме `search.mode: groups`**: в `top_n` члены группы за пределами `top_k` в кандидаты не попадают, и шаг падает
с `NearDuplicateError`. QUERY — `BottleCrop.box_crop` запроса, не крупнее 1600 px, один на все запросы бутылки; ELEMENT — картинка позиции
из коллекции (`Candidate.image`, вся бутылка каталожного фото) и карточка: название, винодельня, винтаж, сорт, категория, сахар, игристость,
крепость, выдержка. Карточка берётся из метаданных точки; `cards` в конструкторе подменяет её полями каталога (`cards_from_rows` по строкам CSV,
`Pipeline` передаёт их из своего каталога сам) — это нужно для коллекций, собранных до появления поля `aging_or_reserve` в метаданных. Ответ модели
строго ограничен схемой: slug одной из позиций запроса либо `not_found`; правила винтажа (`compare_year_*`) одни для обоих кругов.

Почему два круга: прогон 2026-09-28 (`reports/pipeline/2026-09-28_17-39-46`, модель смотрела только группу top-1) ошибся на 15 фото из 125
с ответом; на 8 из них верная группа была второй или четвёртой, а модель либо выбрала позицию чужой группы, либо отказала, либо ответ дала
одиночка без проверки. На 36 фото без ответа, где поиск дал кандидатов, 16 ответов ушли от одиночек без модели. Стоимость: на тесте с `group_margin: 0.07`
не больше 1.85 запроса на фото с кандидатами (200 групповых и до 98 финалов на 161 фото) против 0.67 при одной группе; фото с финалом
ждёт два запроса подряд.

`not_found` в финале либо во всех группах без одиночек даёт `UnmatchedBottle` с наблюдениями модели в `detail`. Ошибка API, таймаут или
нарушение схемы на любом запросе — `NearDuplicateError`, top-1 вместо ответа не подставляется; полный ответ модели без base64 и без ключа
пишется на каждый запрос в `trace_dir/<uuid бутылки>/group<N>.json` (N — номер группы среди кандидатов) и `final.json`, если директория задана.
Запросы идут параллельно, не больше 32 разом.

## Настройки

Модель, параметры генерации, маршрутизация провайдера и таймаут — в `config.yaml` рядом с модулем, загрузчик `configs.py`;
свой файл — `NearDuplicateResolver(settings=load_config(Path(...)))`. Ключ — `OPENROUTER_API_KEY` из `.env` в корне проекта или из окружения,
без него вызов завершается ошибкой с подсказкой; `OPENROUTER_MODEL` перекрывает модель из конфига.
