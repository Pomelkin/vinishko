# Нормализация фото бутылок вина

Прототип предобработки для поиска по фото. Из картинки вырезаются бутылки вина: строго вертикально, горлышком вверх, фон вне маски залит серым `[124, 116, 104]`. Кроп — полоса бутылки на высоте основной этикетки: по ширине вся бутылка, по высоте этикетка с запасом 20% её высоты вверх и вниз, но не дальше маски бутылки. Так целая бутылка с полки и крупный план этикетки из WineSensed дают кадры одного масштаба: этикетка занимает около 70% высоты окна. Запас задаёт `crop.padding_y`; большое значение, например `--set crop.padding_y=10`, даёт всю бутылку без полей. Это среднее нормализации ImageNet, на входе энкодера оно превращается в нули; заливка делает фон одинаковым у запроса с реальным фоном и у каталожного фото на белом. Размытие осталось опцией: `--set background.mode=blur`. Годной считается целевая бутылка с читаемой основной этикеткой: для неё сохраняются кроп, маска этикетки и вырезка под OCR. Остальные найденные бутылки возвращаются отказами с причиной и маской, их показывает интерфейс. Если виден короткий обрубок бутылки, обычно крупный план, кроп идёт без поворота: ось у такой маски неустойчива.

```
картинка ─► SAM3 «wine bottle» ─► кандидаты
         ─► логистическая регрессия ─► целевые бутылки
         ─► проверка этикетки (SAM3 «wine label», без крышек и горлышек) ─► годная бутылка BottleCrop с кропом или отказ RejectedBottle Rejection
         ─► на каждую годную: кроп бутылки, маска и вырезка этикетки, JSON
         ─► годных нет ─► кропов нет, только отказы с причинами
```

| Файл             | Что делает                                                                                                                |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `normalize.py`     | нормализация, есть`--selftest`                                                                                   |
| `normalize.toml`   | конфиг, все параметры с комментариями                                                              |

## Установка

Нужны [uv](https://docs.astral.sh/uv/) и GPU с CUDA. Зависимости ставятся из корня репозитория командой `uv sync`.

Веса SAM3 (`sam3.pt`, 3,4 ГБ) скачиваются сами при первой загрузке модели в кэш пользователя: `~/.cache/vino` на Linux, `%LOCALAPPDATA%\vino\Cache` на Windows, `~/Library/Caches/vino` на macOS. Качаются параллельно диапазонами в 8 потоков, сверяются по sha256 и появляются в кэше только целыми. Официальный репозиторий https://huggingface.co/facebook/sam3 закрыт подтверждением доступа, поэтому источник — открытая копия того же файла на ModelScope. Свои веса задаются путём в `segmentation.model` в конфиге или `--set segmentation.model=путь`; без этого параметра веса берутся из кэша. Проверить, что в скачанном файле только тензоры:

```bash
uv run python -c "import torch; torch.load('$HOME/.cache/vino/sam3.pt', weights_only=True, map_location='cpu'); print('ok')"
```

Веса распространяются под SAM License от Meta, в ней есть пункт о торговых ограничениях.

## Запуск

Команды запускаются из корня репозитория:

```bash
N=vinishko.pipeline.steps.normalization
uv run python -m $N.normalize photo.jpg                           # одна картинка
uv run python -m $N.normalize images/ --set output.dir=/data/out  # папка, параметр конфига из командной строки
uv run python -m $N.normalize --selftest                          # проверка геометрии и метрик на синтетике, без модели
uv run python -m scripts.normalize_dataset run datasets/<имя>     # разметка датасета в normalization.jsonl, без кропов
uv run python -m scripts.normalize_dataset bench datasets/<имя>   # подбор --workers-per-gpu для run на этой машине
```

Для каждой принятой бутылки нормализация создаёт кроп в памяти как `BottleCrop.crop`. Куда он попадёт дальше, решает вызывающий код: CLI `normalize` и отладочный CLI пайплайна сохраняют JPEG локально, визуальный поиск сразу считает вектор, а `build_catalog` записывает кроп в отдельное хранилище каталога. Команда `scripts.normalize_dataset run` сохраняет в `normalization.jsonl` только разметку для повторного построения кропа из исходного фото; сам JPEG она не сохраняет. Поэтому в папках исходного каталога, теста и размеченного датасета кропов может не быть.

Из кода: `Normalizer()` без аргументов берёт `normalize.toml` рядом с модулем и устройство из `segmentation.device` (`auto`, `cpu` либо `cuda:<индекс>`), которое перекрывает переменная окружения `NORMALIZER_DEV`; `auto` — `cuda:0`, если CUDA доступна, иначе `cpu`; заданное проверяется. На CUDA SAM3 считается в half, на CPU во float и в разы медленнее. `Normalizer(img)` и `Normalizer.annotate(path)` отдают список, где каждая найденная бутылка это `BottleCrop` (годная: маски бутылки и этикетки, угол поворота и готовый RGB-кроп для энкодера с матрицами перехода в `crop_info`) или `RejectedBottle` (отказ: причина `NormalizationReason`, пояснение с числами, маска бутылки для интерфейса). Если в списке нет ни одного `BottleCrop`, дальше по пайплайну идти нечему. Обе структуры общие для всего пайплайна и описаны в `vinishko/pipeline/structs.py`; шаги друг о друге не знают, их связывает оркестратор `vinishko/pipeline/pipeline.py`: поиск получает список `BottleCrop`, реранкер — `BottleCandidates` либо `UnmatchedBottle` с кропом внутри, а бутылка, забракованная поздним шагом, становится в разметке `RejectedBottle` с тем же `uuid` через `BottleCrop.reject`. Причины отказа у каждого шага свои, наследник `structs.Reason` с `title` и `description` для интерфейса. В `normalization.jsonl` годная бутылка пишется без кропа, `BottleCrop.markup()`.

Модель загружается один раз за запуск, около 30 секунд. Дальше около 0,25 с на картинку на RTX 3080: 0,14 с энкодер изображения, 0,07 с все четыре промпта одним батчем, остальное — метрики и полигоны на CPU. Если бутылка в кадре мелкая, этикетка ищется вторым проходом SAM3 по вырезке бутылки, это ещё около 0,2 с на такую бутылку.

Для датасетов с мелкими фото, WineSensed 480×640 и Open Food Facts до 400 px, вход модели можно уменьшить: `--set segmentation.imgsz=672` даёт 0,13 с на картинку. На 150 фото WineSensed статусы те же, что при 1008, средний IoU масок бутылки 0,992 и этикетки 0,987. Размер берётся кратным 336, это 14 px патч × 24 патча окно внимания: тогда окна ложатся без паддинга. Калибровка отбора обучена на 1008, поэтому для боевых запросов с крупными фото размер не менять.

## Выход

На каждую годную бутылку четыре файла рядом, `N` — номер бутылки на картинке. Бутылка без годной основной этикетки не вырезается:

| Файл                  | Что внутри                                                                                                                                  |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `<имя>_bN.jpg`       | кроп бутылки                                                                                                                              |
| `<имя>_bN.json`      | описание, см. ниже                                                                                                                     |
| `<имя>_bN_label.npz` | маска этикетки, сжатый bool-массив размером с`label_box`: `np.load(path)["mask"]`                              |
| `<имя>_bN_label.png` | вырезка этикетки под OCR: оригинал в полном разрешении, повёрнут вместе с бутылкой |

```json
{
 "source": "images/DSC_0287_d429be497e.webp",
 "uuid": "5f0c1d6e9b7a4c2f8e3d1a0b9c8d7e6f",
 "bottle_box": [1011, 2202, 2234, 3835],
 "bottle_score": 0.9847,
 "bottle_angle": -34.32,
 "bottle_crop": "DSC_0287_d429be497e_b1.jpg",
 "bottle_crop_matrix": [[0.825905, -0.56381, 797.051182], [0.56381, 0.825905, -2242.088177]],
 "label_box": [1305, 2842, 1982, 3538],
 "label_mask": "DSC_0287_d429be497e_b1_label.npz",
 "label_crop": "DSC_0287_d429be497e_b1_label.png"
}
```

Все координаты в пикселях оригинала после EXIF-поворота, боксы `[x1, y1, x2, y2]` включительно. `bottle_crop_matrix` — аффинная матрица 2×3 из оригинала в кроп бутылки. Маска этикетки лежит в боксе этикетки: пиксель оригинала `(x, y)` соответствует `mask[y - y1, x - x1]`.

`bottle_angle` равен 0, если виден короткий обрубок бутылки: её длина меньше `fallback.min_aspect` ширин, обычно это крупный план, обрезанный кадром. Ось у такой маски неустойчива, кроп идёт без поворота; запас и заливка фона те же.

Если годных бутылок нет, кропов нет вовсе: причины лежат в `RejectedBottle` разметки.

## Отбор и проверка этикетки

Логистическая регрессия отбирает целевые бутылки среди кандидатов SAM3 по признакам маски и картинки, порог 0.49. Затем проверяется основная этикетка. Первая несработавшая проверка даёт причину отказа `NormalizationReason`:

| `NormalizationReason` | Что значит                                                                                                                                                                                                                    | Параметр                                      |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| `not_target`          | бутылка не целевая: скор отбора ниже порога                                                                                                                                                        | `selection.threshold`                               |
| `over_limit`          | годных бутылок в кадре уже достаточно                                                                                                                                                                  | `selection.max_bottles`                             |
| `bottle_too_small`    | бутылка слишком далеко                                                                                                                                                                                             | `selection.min_bottle_px`                           |
| `no_label`            | этикетки закрывают меньше 10% площади бутылки                                                                                                                                                     | `label.min_cover`                                   |
| `not_a_label`         | найдена наклейка, но не основная этикетка: акцизная марка уже 30% ширины бутылки или наклейка у горлышка, ближе 0,3 длины бутылки | `label_crop.min_width_frac`, `label.min_position` |
| `label_partial`       | этикетка закрывает меньше 30% полосы бутылки на своей высоте: повёрнута боком или закрыта                                                                     | `label.min_fill`                                    |
| `label_too_small`     | короткая сторона этикетки меньше 40 пикселей оригинала                                                                                                                                   | `label.min_label_px`                                |
| `label_blurry`        | этикетка размыта: дисперсия лапласиана ниже 300                                                                                                                                                  | `label.min_sharpness`                               |

Положение этикетки вдоль бутылки проверяется только у бутылки, видимой целиком: длина не меньше 2,6 ширины, `label.min_length_ratio`. У крупного плана, где бутылка обрезана кадром, неизвестно, где горлышко. Сама обрезанность причиной отказа не является: крупный план с читаемой этикеткой годится.

Логотип на крышке и кольцевая этикетка на горлышке не считаются: SAM3 отдельно ищет «bottle cap» и «bottle neck», этикетки в этих зонах отбрасываются. Акцизные марки уже 30% ширины бутылки тоже не считаются.

Пороги подобраны на 260 кропах, где видимость и читаемость этикетки отмечены вручную. На них правила отбраковали 63 из 71 бракованной бутылки и потеряли 9 из 189 хороших. Замер сделан до того, как из правил убрали отказ `bottle_hidden` за короткую видимую часть бутылки; после этого он не повторялся.

## Калибровка

```bash
uv run python -m vinishko.pipeline.steps.normalization.calibrate                                 # images/ и labels.json в этой папке
uv run python -m vinishko.pipeline.steps.normalization.calibrate --images /data/photos --beta 2  # порог сильнее в пользу полноты
```

Скрипт прогоняет SAM3 по размеченным картинкам, считает 16 признаков кандидатов и обучает логистическую регрессию с групповой кросс-валидацией. Результат пишется в `calibration.json`. Формат разметки:

```json
{"имя.webp": {"decision": "ok", "targets": [{"box": [x1, y1, x2, y2], "truncated": false}]}}
```

`decision` бывает `ok`, `no_target` или `ambiguous`. `truncated` ставится, только если бутылка уходит за край кадра. На 375 размеченных картинках модель даёт точность 0.89 и полноту 0.91, порог по уверенности SAM3 даёт 0.80 и 0.89.

## Ограничения

- **Перспектива.** Бутылка, снятая сверху или сбоку, стоит вертикально по оси, но на глаз выглядит наклонённой.
- **Сцены с множеством бутылок.** На стеллажах и столах отбор ошибается чаще, а второй проход SAM3 по каждой мелкой бутылке заметно добавляет время.
- **Не-вино.** Классификатора вина нет, вино от водки отличают только промпт и уверенность SAM3.
- **Нехватка видеопамяти на WSL.** Если GPU делят несколько процессов, WSL не падает с ошибкой, а переносит данные в системную память, и SAM3 работает в десятки раз медленнее.
