# API

Структура приложения:

```text
app/
  main.py, schemas.py       # основной API распознавания
  services.py              # HTTP-подключение микросервисов
  sommelier/               # код, промпты, база знаний и тесты сомелье
  whatis/                  # код, промпт, справочник и тесты признаков вина
  frontend/                # статические файлы и проверка фронтенда
```

## Веб-интерфейс

После запуска основного приложения откройте `http://127.0.0.1:8000/`.
Страница раздаётся самим FastAPI; сборка фронтенда не требуется.
Доступны загрузка фото, маски и выбор бутылок, карточки каталога и кандидатов,
признаки неизвестного вина, отдельный вызов whatis, чат с подсказками,
загрузка истории по UUIDv7 и удаление диалога. Через «Задать карточку вина вручную»
можно открыть чат без фото и передать до пяти альтернатив.
Идентификатор последнего диалога сохраняется в браузере; для продолжения после
перезагрузки нажмите «Загрузить историю» в разделе «Диалог и история».

Для AI-функций запустите микросервисы отдельно (см. раздел «Микросервисы» ниже).
Кнопка «Проверить API» показывает состояние основного приложения.
«Только признаки» отправляет исходное фото в whatis (основная бутылка, JPEG/PNG/WebP/GIF до 10 МиБ).
При обычном распознавании автоматический запрос признаков по умолчанию выключен.
Чтобы включить его для каждой отвергнутой бутылки, задайте `AUTO_WHATIS = True` в начале `main.py` и перезапустите основной API.

FastAPI поверх пайплайна. Запуск из корня:

```bash
python -m vinishko.app --host 0.0.0.0 --port 8000        # по умолчанию 127.0.0.1:8000; --search-config, -c/--norm-config, --pipeline-config, --no-resolve
uvicorn vinishko.app.main:app --port 8000                 # то же с конфигами по умолчанию
```

Пайплайн поднимается при старте: нормализация, поиск, второй уровень и каталог по своим конфигам (`steps/normalization/normalize.toml`,
`steps/vis_searcher/config.yaml`, `steps/near_duplicates/config.yaml`, `pipeline/config.yaml`). Устройства — `NORMALIZER_DEV` и `VIS_SEARCHER_DEV`,
ключ модели второго уровня — `OPENROUTER_API_KEY`, ключ qdrant — `QDRANT_API_KEY`. Запросы к пайплайну идут по одному под замком:
SAM3 и engine TensorRT не рассчитаны на параллельные вызовы из одного процесса; параллелизм — несколько процессов.

Каталог по умолчанию — `vinishko/app/catalog.csv` (копия `datasets/hack-vine/catalog/catalog.csv`, путь в `pipeline/config.yaml`): читается
при старте целиком в память, строка позиции уходит в ответ у выбранной позиции и у каждого кандидата. При старте каждая позиция коллекции
поиска сверяется с каталогом; если хоть одной нет — сервис не поднимается (коллекция и каталог из разных выгрузок).

## `POST /recognize`

Multipart-поле `image`: jpeg, png, webp, heic. Ответ — бутылки, дошедшие до поиска, по убыванию скора отбора: с выбранной позицией либо
с отказом поиска или второго уровня, у всех маска. Объекты, которые нормализация не сочла целевой бутылкой с читаемой этикеткой, в список
не входят, их число — `ignored`. Координаты в пикселях фото после EXIF-поворота (`image.width`, `image.height`):

```json
{
  "image": {"width": 3024, "height": 4032},
  "bottles": [
    {
      "uuid": "…", "index": 1, "score": 0.98,
      "polygons": [[[x, y], …]], "label_polygons": [[[x, y], …]], "bbox": [x1, y1, x2, y2],
      "status": "matched",
      "match": {"slug": "…", "score": 0.83, "group": "…",
                "image_url": "/catalog/images/<slug>.jpg", "catalog": {"Название вина": "…", "Винодельня": "…", …},
                "source": "ndr_v5", "checklist": {"maker": {"observation": "…"}, "profile": {…}, "year": {…}}},
      "candidates": [], "rejection": null
    },
    {
      "uuid": "…", "index": 2, "score": 0.91, "polygons": [[[x, y], …]], "label_polygons": [[[x, y], …]], "bbox": [x1, y1, x2, y2],
      "status": "rejected", "match": null, "candidates": [],
      "rejection": {"stage": "search", "reason": "no_match", "label": "Нет в каталоге", "description": "…",
                    "detail": "средний косинус лучшей группы 0.612, порог 0.7", "message": "Нет в каталоге: средний косинус лучшей группы 0.612, порог 0.7"}
    }
  ],
  "ignored": 1,
  "timings_s": {"normalization": 0.41, "search": 0.05, "resolve": 2.3}
}
```

`status`: `matched` — выбрана одна позиция, `match.catalog` — строка каталога целиком, `match.source` —
`ndr_v5` (модель выбрала среди группы) либо `vector` (в группе одна позиция). Используется групповой пайплайн с `NearDuplicateResolver`.
`rejected` — отказ, `rejection.stage` говорит, какой шаг: `search` (нет похожих в каталоге) либо `resolve`
(модель не нашла точного совпадения в группе); `candidates` — сервис поднят с `--no-resolve`, кандидаты поиска как есть, у каждого те же
`slug`, `score`, `group`, `image_url` и `catalog`, что у `match`, без `source` и `checklist`. Фото, где ни одна
бутылка не дошла до поиска, — пустой список и `ignored` со счётом. Файл, который не читается как изображение, — 400.

## `GET /catalog/images/{name}`, `GET /health`

Картинка позиции из хранилища коллекции, JPEG; путь — `image_url` из ответа, имя сейчас `<slug>.<формат сборки>`. `/health` — коллекция, модель поиска и её входы, режим поиска,
модель второго уровня, источник и размер каталога.

## Проверка

`python -m vinishko.e2e --url http://127.0.0.1:8000` прогоняет тестовый набор через поднятый сервис и считает метрики классификации
итогового ответа; разбор шагов с дампами — `python -m vinishko.pipeline.evaluate_pipeline`.

## Микросервисы

Основной API обращается по HTTP к [AI Sommelier Service](https://github.com/Pomelkin/vinishko/tree/ai-somelier-service)
на `127.0.0.1:8805` и [whatis-service](https://github.com/Pomelkin/vinishko/tree/whatis-service) на `127.0.0.1:8810`.
Они запускаются отдельно; все клиентские запросы можно отправлять на основной API (`127.0.0.1:8000`).
Новые маршруты доступны в общей `/docs` и `/openapi.json`.

### Запуск всего приложения

Откройте три терминала в корне проекта `E:\Pycharm Projects\vinishko` и в каждом активируйте то же Python-окружение, что используется для основного API:

```powershell
.\.venv\Scripts\Activate.ps1
```

В корневом `.env` должны быть ключ OpenRouter и путь к сохранённым диалогам:

```dotenv
OPENROUTER_API_KEY=ваш_ключ
SOMMELIER_DATA_DIR=vinishko/app/sommelier/data/sessions
```

Если для OpenRouter нужен proxy, задайте `openrouter_http_proxy` в корневом `.env`.
Оба микросервиса читают его непосредственно при запросах к OpenRouter; `HTTP_PROXY` и `HTTPS_PROXY` для них настраивать не нужно.
Если `openrouter_http_proxy` отсутствует или пуст, эти запросы идут напрямую, без proxy из системного окружения.
Настройка действует только на запросы моделей и не меняет переменные окружения или соединения между сервисами.
Уже заданные переменные окружения имеют приоритет над `.env`.

Терминал 1 — основной API и фронтенд:

```powershell
python -m vinishko.app
```

Терминал 2 — сомелье:

```powershell
python -m uvicorn vinishko.app.sommelier.main:app --env-file .env --host 127.0.0.1 --port 8805 --workers 1
```

Терминал 3 — признаки неизвестного вина:

```powershell
python -m uvicorn vinishko.app.whatis.main:app --env-file .env --host 127.0.0.1 --port 8810 --workers 1
```

Откройте `http://127.0.0.1:8000/`. Отдельная сборка или сервер фронтенда не нужны.
Оставьте все три процесса работающими; Ctrl+C останавливает процесс в соответствующем терминале.
Если порт занят, остановите прежний процесс этого сервиса перед повторным запуском.
Проверка микросервисов: `http://127.0.0.1:8805/health` и `http://127.0.0.1:8810/health`.
При указанном `SOMMELIER_DATA_DIR` диалоги сохраняются в `vinishko/app/sommelier/data/sessions/`;
без этой настройки сомелье использует `data/sessions/`. Для сомелье оставьте один worker.

Параметры подключения находятся в начале `services.py`: `SOMMELIER_URL`, `WHATIS_URL`,
`SERVICE_TIMEOUT_SECONDS` (65 секунд на запрос), `MAX_IMAGE_BYTES` (10 МиБ).
Если основной API работает в контейнере, замените адреса на имена сервисов в его сети
или `host.docker.internal` для сервисов на хосте. Внутренний HTTP-клиент использует `trust_env=False`,
поэтому proxy из окружения не влияет на эти соединения. Настройки OpenRouter и его proxy остаются в микросервисах.

Вместо переменной ключа оба сервиса поддерживают `OPENROUTER_API_KEY_FILE`.
Git и отдельные рабочие каталоги для запуска больше не нужны. Основное приложение запускается прежней командой
`python -m vinishko.app`; при его старте доступность микросервисов не проверяется.

### Неизвестное вино

Параметр `AUTO_WHATIS = False` в начале `main.py` отключает автоматические обращения к whatis из `POST /recognize`.
Отдельный `POST /v1/predict` и кнопка «Только признаки» работают независимо от этого параметра.
При `AUTO_WHATIS = True` (после перезапуска основного API) `POST /recognize` отправляет JPEG-кроп **всей отдельной бутылки** (`box_crop`)
в whatis, если поиск или второй уровень вернул отказ. Для найденных позиций, кандидатов без второго уровня
и объектов, отброшенных нормализацией, whatis не вызывается. Несколько неизвестных бутылок обрабатываются последовательно.
Каждый такой вызов может расходовать токены OpenRouter и увеличивает время ответа.

Исходные `status`, `rejection` и `match` сохраняются. У бутылки добавляются поля:

```json
{
  "unknown_wine": {"category": "Красное", "brand": "Фанагория"},
  "unknown_wine_error": null
}
```

Значение `Не удалось определить` — штатный отказ модели по признаку. При недоступном сервисе
распознавание возвращает HTTP 200 с исходным результатом и, например,
`"unknown_wine_error": {"status_code": 503, "detail": "Микросервис недоступен"}`;
`unknown_wine` будет `null`. У остальных бутылок оба поля `null`.
Общее время вызовов whatis находится в `timings_s.whatis`.

Отдельный `POST /v1/predict` принимает multipart-поле `image` (JPEG, PNG, WebP, GIF до 10 МиБ):

```powershell
curl.exe --noproxy '*' -F 'image=@C:\path\to\bottle.jpg' http://127.0.0.1:8000/v1/predict
```

Ответ HTTP 200: `{"category": "Красное", "brand": "Фанагория"}`. Неверный формат — 415,
слишком большой файл — 413, ошибка провайдера — 502, отсутствие его ключа — 503.

### Чат с сомелье

Клиент создаёт новый UUIDv7 для каждого диалога. Передайте `match.catalog` из `/recognize` как `wine`;
`candidates` — обязательный список из 0–5 альтернативных карточек (можно взять `candidate.catalog`
из ответа поиска без второго уровня). Основной API пересылает карточки без переименования колонок.

```http
POST /v1/sessions/01993959-0000-7000-8000-000000000001
Content-Type: application/json

{"wine": {"Название вина": "Кокур", "Категория": "Белое"}, "candidates": []}
```

Ответ HTTP 201:

```json
{"session_id": "01993959-0000-7000-8000-000000000001", "message": {"role": "assistant", "content": "Описание и совет по подаче", "suggestions": ["Как подавать?"]}}
```

Далее отправляйте `POST /v1/sessions/{session_id}/messages` с `{"content": "С чем подавать?"}`
(1–4000 символов после удаления пробелов по краям). Ответ HTTP 201 имеет тот же формат, `suggestions` — `null`.
`GET /v1/sessions/{session_id}` возвращает HTTP 200 с `{"session_id": "…", "messages": [...]}`.
`DELETE /v1/sessions/{session_id}` возвращает HTTP 204 без тела. История хранится в сервисе сомелье.

Ошибки сервисов передаются с исходным HTTP-кодом и `detail`: 404 — нет сессии, 409 — UUID уже занят,
422 — невалидные данные, 502 — сбой провайдера, 503 — нет ключа. Дополнительно основной API возвращает
503 при невозможности подключиться, 504 при таймауте, 502 при ошибке соединения или невалидном ответе сервиса.
Автоматических повторов нет: запрос создания диалога или отправки сообщения мог уже выполниться до таймаута.
