# Сканер российских вин — frontend

React + TypeScript + Vite. Мобильный интерфейс по пяти предоставленным MHTML-макетам «Своё Вино». Backend, CV, OCR, база каталога и LLM **не реализованы**. Существующий Python-проект в родительском каталоге не изменён.

## Запуск

Требуется Node.js 22.12+ (или Node.js 20.19+) и npm.

```powershell
cd frontend
npm ci
Copy-Item .env.example .env.local
npm run dev
```

Откройте http://localhost:5173. Переменные по умолчанию уже включают mock-режим, поэтому копирование `.env.example` необязательно.

```powershell
npm test
npm run build
npm run preview
npm run test:e2e
```

Сквозные тесты по умолчанию используют установленный Microsoft Edge. Для Chromium:

```powershell
npx playwright install chromium
$env:PW_CHANNEL = 'chromium'
npm run test:e2e
```

Playwright сам запускает Vite, если приложение ещё не работает. В CI задайте установленный браузер через `PW_CHANNEL`. Скриншоты сохраняются в `qa/`, отчёт — в `playwright-report/`.

## Как попробовать

На главной нажмите **«Попробовать на примере» → «Открыть демофото»**. По умолчанию показаны две бутылки: одна с точным совпадением, другая с похожими вариантами. Нажмите на силуэт или доступную кнопку под фото. Кнопка «Подробнее о вине» открывает внутреннюю карточку. Browser Back возвращает фото и открытый попап. Перезагрузка результата также восстанавливает сессию.

В том же окне можно выбрать все девять сценариев: одно/несколько совпадений, смешанный результат, неизвестная бутылка с рекомендациями/без них, отсутствие бутылок, долгое ожидание, ошибка, отмена и перезапуск. Длительная имитация занимает 14 секунд, сообщение о задержке появляется через 6 секунд. «Подождать еще» ждёт тот же запрос. В сценарии ошибки повторная попытка намеренно снова ошибочна; выберите другой сценарий для успеха. У HTTP-адаптера нет искусственной задержки.

## Что умеет интерфейс

- Камера: запрос после нажатия, предпочтительно задняя, превью, затвор, пересъёмка и подтверждение. Треки останавливаются при снимке, закрытии и уходе со страницы. При отсутствии browser camera API используется нативный `capture` input. Отказ в доступе предлагает галерею и нативную камеру.
- Галерея: JPEG/PNG/WebP, до 20 МБ, проверка декодирования, ориентация EXIF средствами браузера. Изображения нормализуются в JPEG до 2400 px по длинной стороне. HEIC/HEIF честно отклоняется с просьбой экспортировать в JPEG/PNG. Ограничение декодированного изображения — 80 Мп.
- Контуры: нормализованные полигоны, SVG clipping, `contain`, затемнение фона, масштаб выбранного силуэта 1.045 вокруг собственного центра. Пересечения разрешаются по меньшей площади, затем по id. Все бутылки доступны отдельными кнопками с клавиатуры.
- Один модальный sheet: совпадение, похожие вина, краткая карточка кандидата. Нативный `<dialog>` ограничивает фокус и блокирует фон; Escape, крестик, backdrop и свайп вниз закрывают окно. Свайп из содержимого допустим только с верхней границы прокрутки; ручка работает всегда.
- Поиск по названию, производителю, сорту и региону; фильтры по цвету и региону; локальные подсказки к гастросочетаниям.
- Сессии `/scan/:scanId` содержат Blob, результаты, выбор, состояние sheet и прокрутку. Изображения не хранятся в URL или localStorage.

## Ограничения mock-режима

Произвольная фотография **не распознаётся**: она нормализуется, сохраняется и показывается без выдуманных контуров. Есть явное предложение открыть подготовленный пример. Фото не отправляются сторонним сервисам.

Демопримеры — SVG-композиции из реальных студийных фотографий предоставленного каталога. Контуры вручную обведены в координатах этих фотографий и не являются результатом CV. Перед демозапросом композиция растеризуется в JPEG. Это позволяет точно проверить UI нескольких бутылок, но не качество сегментации на полевых снимках. Загруженный произвольным способом файл считается пользовательским вводом, даже если выглядит как демо.

Каталог небольшой, `slug` локальные. Часть описаний, сортов, температур и сочетаний — демонстрационное наполнение, не справочник подтверждённых свойств продукта. Доступные народные рейтинги перенесены из референсов и не актуализируются. Неизвестные рейтинги, крепость и F1 равны `null`; ошибочные `135%` и `undefined` не перенесены. Рейтинги не являются confidence.

## Подключение backend

```dotenv
VITE_API_MODE=http
VITE_API_BASE_URL=https://your-api.example/api
```

Перезапустите Vite / пересоберите приложение. React-компоненты не меняются. Backend должен реализовать проект контракта из [API.md](API.md), принимать нормализованную фотографию и возвращать полигоны относительно **именно этого изображения**. При отдельном origin настройте CORS. Не добавляйте секреты в `VITE_*`: они публичны в браузерной сборке.

## Камера на телефоне

`getUserMedia` требует безопасного контекста. `http://localhost` на компьютере допустим; `http://192.168.x.x:5173` на телефоне обычно не даёт доступа к камере. Для проверки на телефоне используйте HTTPS reverse proxy перед Vite с сертификатом, которому доверяет телефон (например, локальный CA), либо HTTPS-туннель. Установите доверенный сертификат на телефон, откройте HTTPS-адрес и разрешите камеру. Нативный `capture` fallback зависит от браузера. При размещении под HTTPS будущий API тоже должен быть HTTPS.

Для production выполните `npm run build` и отдавайте `dist/` через статический HTTPS-хостинг с fallback всех маршрутов на `index.html`. Веб-сервер для распознавания в эту работу не входит.

## Хранение и ограничения браузера

IndexedDB: база `svoe-vino-scans`, хранилище `sessions`. Очистка выполняется при старте приложения: срок 7 дней, максимум 10 последних сессий. Это локальные фото на устройстве пользователя; очистка данных сайта удаляет их. При запрете или заполнении IndexedDB сохраняется рабочая копия в памяти и отображается предупреждение, что перезагрузка может потерять фото. Object URLs создаются заново из Blob и освобождаются при размонтировании.

Архитектура: [ARCHITECTURE.md](ARCHITECTURE.md). Результаты проверок и визуальная сверка: [qa/VERIFICATION.md](qa/VERIFICATION.md).

## Ресурсы и референсы

Логотип, иллюстрации, фотографии и шрифт Playfair взяты из предоставленных MHTML и сайта https://vino-svoe.ru/ для воспроизведения хакатонного макета. Сторонние скрипты, аналитика и трекеры в приложение не включены. Права на исходные материалы принадлежат их правообладателям; приложение не представляет собой официальный сервис.

`tools/extract_references.py` — вспомогательное извлечение инертных архивов; требует Python, BeautifulSoup и PyMuPDF. `tools/prepare_assets.py` — подготовка ресурсов и ручных контуров. Эти скрипты не нужны для запуска: готовые локальные ресурсы уже в `public/assets`. Исходные MHTML не встраиваются в приложение.
