# Архитектура frontend

```text
src/app                 маршруты, контекст действий сканера, оболочка, токены
src/pages               ScannerPage, ScanResultPage, WinePage
src/entities/wine       карточка, изображение, краткое описание, рейтинги
src/features/image-input декодирование, EXIF, нормализация JPEG, камера
src/features/scanning   конечные состояния и владение запросом
src/features/bottle-selection SVG clipping и интерактивные силуэты
src/features/scan-session загрузка и изменение сохранённого результата
src/shared/api          контракт, валидация, mock/http адаптеры, сообщения ошибок
src/shared/storage      IndexedDB, очередь записи, fallback в памяти, очистка
src/shared/geometry     contain, координаты, hit testing, площадь и центр
src/shared/ui           доступный sheet, иконки, жизненный цикл Blob URL
src/mocks               демонстрационный каталог и вручную заданные полигоны
```

Компоненты не импортируют fixtures. Все данные каталога и распознавания приходят через `RecognitionService`. Режим выбирается один раз в `shared/api/service.ts`. Переключение backend не меняет страницы. Mock имеет дополнительный метод подготовки демонстрационного Blob; он доступен только в режиме mock и не входит в контракт backend.

## Процесс

`idle → camera → preparing → recognizing → success / error`, с переходом `recognizing → slow → recognizing`. Отмена переводит в idle и сбрасывает id операции. Повторная попытка создаёт новый id; ранее нормализованный Blob переиспользуется.

Zustand store принадлежит `ScanController`. Он запрещает дубли во время подготовки и ожидания. Каждый асинхронный этап проверяет id операции и AbortSignal до применения результата. Даже сервис, игнорирующий abort, не может перезаписать новую сессию поздним ответом. Навигация с маршрута и размонтирование отменяют текущую операцию.

## Геометрия

SVG viewBox равен размерам исходного нормализованного фото; image, clipPath и полигоны используют одну систему. `preserveAspectRatio="xMidYMid meet"` реализует contain и полосы вокруг изображения. Координаты нажатия переводятся через обратную экранную матрицу SVG. Контур и hit testing поэтому не расходятся после resize. Отдельные кнопки под фото обеспечивают выбор без точного попадания и с клавиатуры.

Поверх фотографии лежит затемнение. Копии фото обрезаются по силуэту, выбранная копия масштабируется 1.045 вокруг центра bbox собственного полигона. Масштабируется только вырезанный объект. При перекрытии hit testing выбирает наименьшую площадь, затем стабильный id. Дорогостоящий фильтр на всю фотографию не применяется.

## Сессия

IndexedDB хранит `scanId`, `imageBlob`, `imageDimensions`, `recognitionResult`, `selectedDetectionId`, `sheetView`, `selectedSimilarWineSlug`, `relevantScrollPositions`, `createdAt`, `source`. Перед переходом к подробной карточке дожидаемся записи полного снимка состояния. Записи сериализованы, чтобы старое обновление sheet не перезаписало новое. Чтение проверяет схему результата и срок хранения.

Blob URL живёт только в UI; после reload создаётся заново. Blob не кодируется в URL или localStorage. Если IndexedDB недоступен, используется Map в памяти с предупреждением. Максимум 10 сессий, срок 7 дней; очистка при запуске.

`/wine/:slug` получает проверенный `location.state.from`, указывающий на сессию. Внутренняя кнопка возврата использует этот маршрут; для прямой ссылки — `/`. Browser Back/Forward работает через React Router и IndexedDB без повторного recognize.

## Доступность

Нативный modal dialog: фокус остаётся внутри, фон inert, Escape и восстановление фокуса; прокрутка body заблокирована. У загрузки есть `role=status`, ошибки озвучиваются, все иконки-кнопки подписаны. Поддерживаются reduced motion, safe areas и dvh. Основные зоны нажатия не менее 44 px. В sheet основной CTA вынесен из прокрутки и не пересекается с плавающей поисковой панелью.

## Интеграция с сервером

По умолчанию выбран HTTP; демонстрационный режим включается только явным `VITE_API_MODE=mock`. Каталог и карточки приходят из CSV через `/api/wines`; первая страница показывает 24 карточки, остальные доступны кнопкой. Регионы фильтра собираются из полученных данных.

`features/sommelier` управляет созданием диалога, вопросами, подсказками, восстановлением истории и удалением через `/api/sommelier/sessions`. В localStorage хранится только идентификатор, сообщения — на сервере. Ошибка после POST требует загрузки истории перед повторным сообщением.

`features/unknown-wine` вырезает область выбранной бутылки и запрашивает `/api/whatis`. Предположения сохраняются в результате сканирования и могут служить контекстом для сомелье. Если масок нет, доступна обработка всего фото.

Маска может содержать несколько компонентов `polygons`; SVG и hit testing используют их все. Поле `polygon` сохраняется для совместимости со старыми сохранёнными сессиями и демонстрационными данными.

Сервер запускается одним процессом FastAPI: исходные маршруты сохранены, `/api` содержит адаптер данных интерфейса. В Docker фронтенд раздаёт nginx из отдельного образа; в разработке API проксирует Vite. Оба варианта используют один origin для браузера.
