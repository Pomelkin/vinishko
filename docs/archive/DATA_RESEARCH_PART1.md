Ключевое различие, которое стоит держать в голове: **Каталог и Эталоны — это то, среди чего
ищем** (индекс), а **eval-сеты — это то, чем ищем** (запросы). Это разные роли, и требования
к ним разные.

### Что означают ML-термины применительно к этим наборам

| Термин | Что это обычно | Что здесь |
|---|---|---|
| обучающая выборка | примеры «вход → правильный ответ», на которых учат модель | **отсутствует полностью** |
| валидационная выборка | размеченные примеры для подбора порогов и сравнения версий | **отсутствует**; Публичный eval-сет не годится, см. раздел 3 |
| тестовая выборка | закрытые примеры для финальной оценки | Приватный eval-сет, нам недоступен |
| метки (labels) | правильный ответ для каждого примера — здесь это правильный slug | есть только в Ключе ответов у кейсодержателя |
| индекс / база поиска | то, среди чего ищется ответ | Каталог + Эталоны |

Когда ниже написано «меток нет», это означает конкретную вещь: **ни для одного из трёх фото
в `/Users/areremkin/Code/wine-hack/data/eval/queries/` не сказано, какому slug из Каталога оно
соответствует.** Правильные ответы лежат в Ключе ответов у кейсодержателя и участникам
не выдаются — своё решение можно проверить только на контрольном прогоне.

## 3. Это обучающая выборка или нет

**Нет.** Разбор по каждому набору отдельно.

### Каталог (`/Users/areremkin/Code/wine-hack/data/strapi/strapi_output0709.csv`)

Это справочник карточек: 2103 позиции с текстовыми полями и slug. Изображений в нём нет,
только имя файла в колонке `Название фото`. Роль — **индекс для поиска и источник содержимого
карточки**, которую сервис отдаёт пользователю.

### Эталоны (подмножество `/Users/areremkin/Code/wine-hack/data/strapi/img/`)

Одно изображение на позицию, и то у 36% Каталога. Для обучения классификатора это непригодно
по трём причинам сразу:

| Признак обучающей выборки | Факт по Эталонам |
|---|---|
| несколько примеров на класс | нет: ровно один кадр на позицию |
| покрытие всех классов | нет: 1337 позиций Каталога без единого изображения |
| тот же домен съёмки, что у запросов | нет: студийный рендер против съёмки у полки |

Роль Эталонов — **векторный индекс для retrieval**, то есть то, с чем сравнивается запрос.

### Публичный eval-сет (`/Users/areremkin/Code/wine-hack/data/eval/queries/`)

Три фотографии без меток. Единственный набор, который по формату похож на обучающий или
валидационный (полевые фото — ровно то, что придёт в продакшене), но:

- правильные slug не выданы — они в Ключе ответов у кейсодержателя;
- трёх примеров не хватило бы даже на валидацию порогов;
- как выяснилось в разделе 7, два из трёх вин вообще отсутствуют в Каталоге.

### Что из этого следует для подхода

- **Supervised-дообучение классификатора невозможно**: 2103 класса, ≤1 пример на класс, и тот
  из чужого домена. Любая «точность», измеренная на Эталонах, будет измерять переобучение.
- Рабочая постановка — **zero-shot / метрический retrieval**: эмбеддинг запроса ищется по
  индексу Эталонов (SigLIP 2 / DINOv2 / CLIP-подобные), плюс текстовый канал через OCR.
- Дообучение возможно только **self-supervised**: из Эталонов синтезируются позитивы
  (кроп этикетки, перспектива, блики, шум, цилиндрическая деформация, фон полки), на них
  учится contrastive-голова. Тот же приём даёт локальный валидационный набор — синтетические
  запросы с заведомо известным slug.
- **Собственная разметка — отдельная задача проекта.** Минимум: 100–200 своих фото бутылок
  в магазине с ручной привязкой к slug Каталога. Без неё нельзя отличить реальное улучшение
  пайплайна от случайного шума.

## 6. Связывание Каталога с Медиа-дампом

### 6.1 Почему это было проблемой

Strapi при загрузке переименовывает файл по правилу
`nameToSlug(<исходное имя>) + "_" + <10 hex> + <ext>`, где `nameToSlug` — это
`@sindresorhus/slugify` с `separator="_"`, `lowercase=false` (транслитерация → decamelize →
замена не-`[A-Za-z0-9]` на `_`). Колонка `Название фото` Каталога хранит **исходное** имя,
поэтому в выданном виде пересечение между ней и именами файлов Медиа-дампа было ровно нулевым.

Правило реконструировано в `/Users/areremkin/Code/wine-hack/scripts/rename_img_to_csv_names.py`
и подтверждено на данных (`Белое брют` → `Beloe_bryut`, `ДНК Аура Меркотан2` →
`DNK_Aura_Merkotan2`, «Цимлянское…» → `Czimlyanskoe…`).

### 6.2 Текущее состояние папки

Скрипт уже применён к 784 файлам: они переименованы обратно в имена из колонки `Название фото`,
поэтому сейчас связывание — прямой lookup по имени. Журнал переименований —
`/Users/areremkin/Code/wine-hack/scripts/rename_journal.json`, откат — флагом `--revert`.
Остальные 1682 файла сохранили Strapi-имена; из них к позициям Каталога относятся только 15
(их поймал второй канал — «имя файла ≈ slug»), а 1667 — это Хвост Медиа-дампа.

### 6.3 Результат связывания

| Канал связывания | Позиций Каталога |
|---|---|
| по `Название фото` (правило Strapi / прямой lookup после переименования) | 763 |
| по имени файла, совпадающему со slug позиции | 542, из них 3 новых |
| **объединение** | **766 из 2103 — 36,4%** |
| агрессивная нормализация поверх остатка | **+0** |
| fuzzy-матч (difflib ≥ 0,86) на выборке 400 позиций | **+0** |

Ноль дополнительных попаданий у fuzzy — это и есть доказательство: оставшиеся 1337 позиций
не «плохо сматчены», их файлов **нет в Медиа-дампе**. Проверено точечно: `usadba-rodnoe-gnezdo-*`,
`olymp-winery-*`, `shato-pino-*` не встречаются в папке ни в одном написании.

### 6.4 Переименование покрытия не меняет

## 7. Публичный eval-сет и скрипт оценки

Источники: `/Users/areremkin/Code/wine-hack/data/eval/queries/` (3 фото),
`/Users/areremkin/Code/wine-hack/data/eval/queries.tsv` (манифест),
`/Users/areremkin/Code/wine-hack/data/eval/participant_test.sh` (скрипт, менять нельзя).

### 7.1 Контракт скрипта

- `POST` multipart, поле **`image`**; endpoint по умолчанию `http://127.0.0.1:8080/v1/eval/predict`.
- Принимается только `200`/`201` и тело `{"slug":"..."}` либо `[{"slug":"..."}]`; всё прочее →
  `predicted_slug: null` (jq-выражение в строках 152–158 скрипта).
- `--connect-timeout 5`, `--max-time 10`. Ответ дольше 10 с засчитывается как промах.
- Запросы строго последовательные, без ретраев и параллелизма → **холодный старт первого
  запроса портит latency всего прогона**; модели греть на старте сервиса.
- Скрипт падает, если выходной файл уже существует.
- `curl --form "image=@file"` выставляет Content-Type по расширению, а файлы Публичного eval-сета
  с расширением `.jpg` физически являются WebP. Определять формат только по содержимому.

Целостность пакета: `cd /Users/areremkin/Code/wine-hack/data/eval && shasum -a 256 -c checksums.sha256`.

3. **Сайты и соцсети виноделен** — 44 производителя закрывают 80% дыры; у крупных

4. **Витрины маркетплейсов и ритейла** — источник и товарных рендеров, и полевых фото сразу.
5. **Собственная съёмка в магазине** — единственный способ получить честный валидационный набор
   в целевом домене; 100–200 фото достаточно, чтобы измерять изменения пайплайна.

## 10. Что из этого следует для пайплайна

Выводы ниже — прямое следствие статистики, а не общие рекомендации.

1. **Сначала данные, потом модель.** Прирост от закрытия пробела в Медиа-дампе (36% → 90%+)
   на порядок больше любого выигрыша от смены бэкбона. До этого тюнинг модели измеряет шум.
2. **Индекс собирается один раз в `catalog.jsonl`**: дедуплицированные 2103 позиции Каталога,
   разобранные из slug атрибуты, привязанный файл Эталона либо явная отметка «эталона нет».
   Позиции без Эталона обязаны остаться в индексе — их ловит только текстовый канал.
3. **Два независимых канала поиска.** CV-канал покрывает 36% Каталога; текстовый канал
   (OCR запроса → fuzzy-матч по `Винодельня` + `Название вина` + `Сорт`) работает на 100%
   позиций, потому что не требует эталонной картинки. Для 64% Каталога OCR — единственный шанс.
   Это, а не «усиление достоверности», и есть причина делать OCR, хотя ТЗ считает его опцией.
4. **Нормализация с двух сторон.** Детект бутылки → кроп этикетки → выравнивание перспективы →
   развёртка цилиндра → подавление бликов, и то же самое применительно к Эталонам: сравнивать
   нужно этикетку с этикеткой, а не полный кадр с рендером. Подсказка кейсодержателя про
   нормализацию подтверждается геометрией: у Эталона этикетка — малая часть кадра,
   у запроса — половина.
5. **Сначала определить объектный класс.** Для 96 семейств разных вин CV приносит кандидатов,
   а год, сахар и сорт из OCR выбирают товар. 16 групп одного объекта (33 позиции), наоборот,
   схлопываются в canonical product id с alias-slug: OCR не должен разводить одну бутылку.
6. **Кадр с несколькими бутылками** — не редкость, а норма съёмки у полки: выбор целевой
   бутылки (центральная или максимальная по площади) должен быть явным шагом пайплайна.
7. **Confidence и сценарий «нет в Каталоге».** Порог по отрыву top-1 от top-2 нужен не ради
   красоты метрики: при покрытии 36% значительная часть запросов не имеет правильного ответа
   в CV-индексе, и честная деградация в «похожие вина» — то, что ТЗ оценивает выше «не найдено».
8. **Валидация до появления настоящих меток** — синтетическая: из каждого Эталона генерируется
   набор псевдо-запросов (кроп, перспектива, блики, фон, шум сжатия), метрика — recall@1/@5
   по известному slug. Это ловит регрессии, но систематически завышает качество: домен всё ещё
   не полевой.
