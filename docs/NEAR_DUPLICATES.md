# Near-duplicates Каталога: чем похожие вина различаются и когда не различаются вовсе

Отдельное исследование по одному вопросу: **всегда ли позиции Каталога, похожие как две капли,
чем-то отличаются — этикеткой, бутылкой, хоть годом, — или бывают полностью одинаковые?**

Ответ короткий: **бутылки различаются всегда, данные — нет.** Ни одной пары позиций Каталога
с собственными Эталонами, которые были бы визуально неразличимы, не нашлось: минимальная
разница между разными позициями в 2,5 раза выше потолка шума перекодирования. Но у 40 позиций
(20 групп) Эталон физически один и тот же файл на двоих — эти неразличимы не потому, что вина
одинаковые, а потому, что так собран Медиа-дамп. И даже там, где разница есть, она падает
до **0,14% площади бутылки** — год «2017» против «2021» размером 12×55 px при ширине бутылки
640 px. Для эмбеддинга это ноль; читается только OCR по кропу этикетки.

Различие почти всегда в оформлении, а не в стекле: у **78% пар** бутылка одна и та же,
меняются этикетка и капсула; полностью разный силуэт — у каждой пятой пары, и часть из них
объясняется не формой, а другим светом при рендере.

Все цифры воспроизводятся `python3 scripts/near_duplicates.py`; картинки по группам раскладывает
`python3 scripts/collect_near_duplicates.py` в `data/near_duplicates/`. Словарь наборов (Каталог,
Эталоны, Медиа-дамп, eval-сеты) — как в `CLAUDE.md` и `docs/DATA_RESEARCH.md`.

## 1. Ответ на главный вопрос

| Уровень | Что измеряли | Результат |
|---|---|---|
| **Физическая бутылка** | 446 проверенных пар позиций: все пары внутри серий плюс все визуально близкие кандидаты | различие есть **у всех 446**, минимальный `max_diff` = **0,356** |
| **Шум кодека** | те же Эталоны, пересохранённые в WebP q=95/80/60 | `max_diff` ≤ **0,141**, доля изменённых пикселей ≈ 0 |
| **Данные Каталога** | привязка Эталонов к slug | **20 групп, 40 позиций** делят один и тот же файл — различить нечем |
| **Размер различия** | самые похожие пары | от **0,14% площади бутылки** (год) до 2% (строка с сортом) |

Разрыв между «шум перекодирования» (0,141) и «минимальная разница между разными позициями»
(0,356) — в 2,5 раза, без единого пересечения. То есть: **если у двух позиций есть свои
собственные рендеры, на них всегда найдётся хотя бы одна контрастная различающая деталь.**
Пиксельно одинаковых пар разных вин в данных нет.

Обратное утверждение неверно: near-duplicate по тексту вовсе не обязан быть похожим на картинке —
редизайн между урожаями меняет бутылку до неузнаваемости (раздел 6).

## 2. Как считалось

1. Каталог дедуплицируется по `Slug` (4147 строк → 2103 позиции), Эталоны привязываются
   штатным связыванием из `scripts/analyze_data.py` — 766 позиций с картинкой.
2. Каждый Эталон нормализуется: кроп по непрозрачным пикселям (753 из 799 файлов в RGBA),
   белый фон, ширина 640 px. Рендеры кадрированы по-разному, поэтому перед сравнением
   подбирается сдвиг — грубо на копии, уменьшенной вчетверо, затем уточнение в полном размере.
3. Скрининг: попарный RMSE по превью 32×64 для всех 799 Эталонов (318 801 пара). Кандидаты
   на точное сравнение — RMSE < 0,06 (для сравнения: 1-й процентиль по всем парам — 0,179).
4. Для кандидатов считается карта разницы, доля пикселей с отличием > 0,10, максимум разницы
   и **горизонтальные полосы различий** — где именно на бутылке лежит отличие и какого оно размера.
   Точно сравниваются все пары внутри серий и все визуально близкие кандидаты — 446 пар;
   остальные заведомо далеки и в точном сравнении не нуждаются.

Пороги откалиброваны на самих данных, а не взяты с потолка:

| Что | `max_diff` | Доля пикселей > 0,10 |
|---|---|---|
| WebP q=95 | 0,031 / 0,084 (медиана / максимум) | 0,00000 |
| WebP q=80 | 0,076 / 0,105 | 0,00001 |
| WebP q=60 | 0,112 / 0,141 | 0,00011 |
| **разные позиции Каталога** | **0,356 — минимум по 446 парам** | от 0,0014 |

Отсюда рабочий порог: `max_diff` < 0,20 — «это тот же самый рендер», выше — «есть реальная
различающая деталь».

## 3. Таксономия: четыре разных явления под одним словом

«Near-duplicate» в кейсе означает четыре разные вещи, и лечатся они по-разному.

| Класс | Что это | Групп | Позиций | Разводится |
|---|---|---|---|---|
| **A** | один Эталон на несколько slug | 20 | 40 | картинкой — никогда |
| **B** | одна серия одного производителя (год / сахар / сорт / крепость) | 92 | 202 | OCR по этикетке + атрибуты из slug |
| **C** | визуально близкие Эталоны вне общей серии | 387 пар | 289 | этикеткой, различие от 0,1% площади |
| **D** | одинаковое название у разных виноделен | 60 названий | 362 | только связкой «винодельня + название» |

Всего в near-duplicate-отношениях участвуют **483 позиции из 2103 (23% Каталога)**; классы
пересекаются (A∩B = 10 позиций, B∩C = 29, A∩C = 12).

## 4. Класс A: один файл на две позиции — единственная настоящая неразличимость

20 групп, 40 позиций. В 19 группах обе позиции принадлежат одной винодельне, в одной —
разным. Природа у них разная, и это важно: только часть — действительно одно и то же вино.

| Природа | Групп | Пример |
|---|---|---|
| картинка заведомо чужая: разный **сорт** | 7 | `derbent-vino-endemy-merlo-…` / `…-saperavi-…` |
| картинка заведомо чужая: разный **цвет вина** | 5 | `abrau-dyurso-az-abrau-bayanshira-beloe-suhoe-12` (белое) / `…-madrasa-krasnoe-suhoe-14` (красное) |
| дубль карточки, атрибутами не разводится | 3 | `aligote-avtorskoe` / `aligote-avtorskoe-vino` (Массандра) |
| один продукт разных лет | 2 | `aligote-barrel-2024` / `aligote-barrel-2025` |
| разный сахар/крепость | 3 | `derbent-vino-endemy-shardone-beloe-bryut-105-125` / `…-suhoe-13` |

Полный список — в выводе `scripts/near_duplicates.py`, секция A.

Три случая стоят отдельного упоминания:

- **`agora-vintage-blanc-de-blancs-extra-brut` (AGORA WINERY) и `blan-de-blan` (Скалистый берег)** —
  одна картинка на вина **двух разных производителей**. Единственная межвинодельческая группа,
  и это точно ошибка выгрузки.
- **`abrau-dyurso-az-abrau-bayanshira-beloe-suhoe-12` и `…-madrasa-krasnoe-suhoe-14`** — белое
  и красное вино с одним рендером. По картинке одна из позиций гарантированно отвечает чужой
  бутылкой.
- **`zhemchuzhnaya-9-aligote-czitron` и `zhemchuzhnaya-9-czitron-shardone` (АРАТТИ)** — обе
  ссылаются на файл «Алиготе, Цитрон бел.сух.webp». При этом у Каталога есть и правильный
  рендер Цитрон/Шардоне — он привязан к дублю `zhemchuzhnaya-9-czitron-shardone-1`:

![Алиготе/Цитрон и Цитрон/Шардоне](img/near-duplicates/wrong-image.png)

Практический вывод: для этих 40 позиций верхняя граница top-1 по CV-каналу — **50%**,
и выбор внутри пары должен делаться текстом, а не картинкой. Отдельно стоит завести правило
«если top-1 и top-2 опираются на один и тот же файл — не показывать уверенность выше 0.5,
а выводить обе карточки».

### Три группы из двадцати чинятся сменой правила привязки

Связывание Каталога с Медиа-дампом идёт по двум каналам: основной — поле `Название фото`,
запасной — «имя файла ≈ slug». Оказалось, что **3 из 20 групп создаёт именно запасной канал**,
а поле `Название фото` у этих позиций указывает на правильные, разные файлы:

| Позиция | `Название фото` (верный файл) | Файл из slug-канала (общий, чужой) |
|---|---|---|
| `derbent-vino-desono-kaberne-sovinon-…` | `Десоно_Каберне Совиньон.webp` | `derbent_vino_desono_kaberne_sovinon_…_6c0917a7d2.webp` |
| `derbent-vino-desono-merlo-…` | `Десоно_Мерло.webp` | `derbent_vino_desono_merlo_…_1527abfea6.webp` |
| `derbent-vino-kavkazian-rkatsiteli-…` | `Белое брют.webp` | `derbent_vino_kavkazian_rkatsiteli_…_4d32763f6b.webp` |

Правильные рендеры Desono Cabernet Sauvignon и Desono Merlot в Медиа-дампе есть и отличаются
пиктограммой на этикетке и надписью сорта (5% площади) — их просто перекрывает эвристика.

Три стратегии привязки дают разный результат:

| Правило | Позиций с картинкой | Конфликтных групп | Позиций в конфликте |
|---|---|---|---|
| оба канала равноправно (как сейчас в `analyze_data.py`) | 766 | 20 | 40 |
| только `Название фото` | 763 | 17 | 34 |
| **`Название фото` + slug-канал как фолбэк** | **766** | **18** | **36** |

Фолбэк-правило строго лучше: сохраняет все 766 позиций с картинкой и убирает две ложные
группы из трёх. Оставшаяся — `agora-vintage-blanc-de-blancs-extra-brut` против `blan-de-blan`:
у второй позиции своего `Название фото` нет вовсе, а файл «Блан де Блан.webp» подтягивается
по имени. Это стоит проверять отдельно: если файл уже занят другой позицией через
`Название фото`, фолбэк применять не надо.

## 5. Класс B: одна серия — то, ради чего нужен OCR

92 группы «винодельня + название без года и объёма», 202 позиции. Чем различаются позиции
внутри группы:

| Различающий атрибут | Групп |
|---|---|
| крепость | 24 |
| год + крепость | 12 |
| **ничего** | **8** |
| год | 5 |
| цвет вина | 5 |
| сорт + крепость | 5 |
| сорт | 4 |
| сахар + крепость | 4 |
| сорт + сахар + крепость | 4 |
| цвет вина + сахар + крепость | 4 |
| остальные сочетания | 17 |

Крепость (числовой суффикс slug) — самый частый разделитель, и он же самый бесполезный:
на этикетке «12,5%» написано мелким шрифтом на контрэтикетке или у самого низа, а в Каталоге
отдельного поля нет — только хвост slug.

**8 групп не разводятся вообще ничем из атрибутов** (18 позиций):

| Винодельня | Серия | Позиции | Эталоны |
|---|---|---|---|
| Шато АЛВИСА | Cantiani Riesling | `cantiani-riesling`, `cantiani-riesling-1` | оба |
| Шато АЛВИСА | Cantiani Rkatsiteli | `cantiani-rkatsiteli`, `cantiani-rkatsiteli-1` | оба |
| АРАТТИ | Жемчужная 9 Цитрон/Шардоне | `zhemchuzhnaya-9-czitron-shardone`, `…-1` | оба |
| Новый Свет | Шардоне Кюве де Престиж | `novyj-svet-shardone-kyuve-de-prestizh`, `…-1` | оба |
| Golubitskoe Estate | Tête de Cheval Blanc de Blancs | `pomeste-golubitskoe-…`, `golubitskoe-estate-…` | нет |
| Кубань-Вино | Высокий Берег Рислинг зелёная серия | `…seriya`, `…seriya-1`, `…seriya-2` | нет |
| АРАТТИ | Жемчужная 9 Каберне Совиньон/Пино Нуар | два slug | нет |
| АРАТТИ | Жемчужная 9 Пино Нуар/Мускат розовый | три slug | нет |

Все четыре группы, которые можно проверить глазами, оказались **не дублями** — различие
видно сразу (доля различающихся пикселей 0,15–0,57):

- **Cantiani Riesling** и `cantiani-riesling-1` — тихое вино в голубой этикетке и **игристое
  брют** с круглой контрэтикеткой; то же у Rkatsiteli. Суффикс `-1` здесь не «повторно
  заведённая карточка», а другой продукт линейки.
- **Новый Свет Кюве де Престиж** и `-1` — один продукт, но **два поколения дизайна**:
  жёлтая этикетка старого образца и белая новая. На полке могут стоять обе.
- **Жемчужная 9 Цитрон/Шардоне** и `-1` — разные бутылки, причём правильный рендер
  достался дублю `-1`, а основной slug получил чужую картинку (см. раздел 4).

Для оставшихся четырёх групп (10 позиций) картинок нет вообще — проверить нечем, и это
самостоятельный вопрос к кейсодержателю: дубли это или разные позиции.

Ограничение выборки: из 92 групп два и более Эталона есть только у **36**, ровно один —
у 2, **ни одного — у 54 групп (113 позиций)**. То есть больше половины серий визуально
непроверяемы в принципе, и их ловит только текстовый канал.

## 6. Насколько мелкое различие: цифры и картинки

Для 446 пар с разными файлами доля различающихся пикселей: p10 = 1,1%, медиана = 5,5%,
p90 = 21,9%. По классам различия:

| Класс пары | Пар | Что это на практике |
|---|---|---|
| различие видно сразу (> 2% площади) | 343 | разный дизайн, разный цвет стекла, другой рендер |
| < 2% площади — строка текста | 98 | надпись сорта, пояс этикетки |
| < 0,5% площади — одна надпись | 5 | год, номер тиража, слово «EXTRA» |
| один и тот же файл | 3 | различить нечем |

Хвост слева — самое интересное.

**Год и только год.** `fanagoriya-primum-alveus-brut-2017-…` против `…-2021-…`: различие
занимает **0,14% площади бутылки**, две детали — римская цифра на горлышке (46×90 px)
и год внизу этикетки (**12×55 px** при ширине бутылки 640 px):

![Primum Alveus Brut 2017 и 2021](img/near-duplicates/year-only.png)

**Сорт и только сорт.** `chteau-le-grand-vostock-cabernet-franc-reserve-…` против
`…-krasnostop-reserve-…`: одна строка каллиграфии, 129×432 px, 0,56% площади:

![Château Le Grand Vostock: Cabernet Franc и Krasnostop](img/near-duplicates/grape-only.png)

Ещё показательнее `fanagoriya-primum-alveus-extra-brut-2014-pino-nuar-…` и
`…-2016-shardone-…`: **разные сорта**, но на лицевой этикетке сорт не напечатан вовсе —
этикетки различает только год. На превью 32×64, по которому шёл скрининг, эта пара даёт
RMSE ровно **0,000**: в низком разрешении это буквально одно и то же изображение.

**Что это значит в пикселях энкодера.** Медианный аспект Эталона w/h = 0,29. Если вписать
бутылку целиком в квадрат 384×384, ширина бутылки станет ≈ 111 px, масштаб к нашим измерениям —
0,17. Год превращается в **2×10 px**, каллиграфия сорта — в 22×75 px. Первое не различимо
никакой моделью, второе — на грани. Вывод прямой:

> Год и мелкий текст на этикетке **не переживают ресайз бутылки под вход энкодера**.
> Ни SigLIP, ни любой другой глобальный эмбеддинг не разведёт позиции, отличающиеся годом.
> Это задача OCR по кропу этикетки в нативном разрешении запроса, а не задача retrieval.

При этом сам запрос с полки пикселей не жалеет: на `q-000002` Публичного eval-сета
(3024×4032) бутылка Массандры занимает около 1400 px по ширине, а год урожая «2023» на
этикетке — порядка 120 px по высоте. Разрешение теряется не в камере, а в пайплайне,
если кропать бутылку целиком и жать её в 384.

### Этикетка, капсула или сама бутылка

Где физически лежит различие у 446 проверенных пар:

| Локализация различия | Пар | Доля |
|---|---|---|
| только в зоне этикетки (нижние 55% высоты) | 185 | 41% |
| смешанное: этикетка + горлышко | 108 | 24% |
| по всему силуэту — другая бутылка или другой рендер | 96 | 22% |
| в основном горлышко и капсула (акцизная марка, номер тиража) | 57 | 13% |

То есть **у 78% пар бутылка одна и та же, различается только оформление**; полностью разный
силуэт встречается у каждой пятой пары — и часть из них объясняется не формой стекла,
а другим освещением при рендере.

Среди самых похожих пар (различие < 2% площади) только **47 из 103** различаются исключительно
этикеткой — остальным помогает горлышко: капсула, акцизная марка, номер тиража. Практически
это значит, что кропать под OCR стоит не одну этикетку, а полосу «горлышко + этикетка».

## 7. Обратная сторона: одинаковый текст ≠ похожая картинка

Нельзя строить логику на допущении «одна серия ⇒ почти одинаковые бутылки». Внутри 36 групп
с двумя Эталонами визуальное расстояние (превью-RMSE, 62 пары) разъезжается от 0,000 при общем
файле до **0,488** при медиане 0,157. Верхний край выше, чем медиана по всем 318 801 паре
Эталонов (0,363): некоторые «near-duplicates» по тексту различаются сильнее, чем два случайных
вина из Каталога.

WINEMAFIA «David» 2020 / 2021 / 2022 — один продукт, три года, полный редизайн на третьем:
другая форма бутылки, другой сургуч, другая этикетка, другое имя производителя на ней:

![David 2020, 2021, 2022](img/near-duplicates/redesign.png)

Цифры к картинке: расстояние от `david` (2020) до `david-2022` — **0,485**, и **772 чужих
Эталона из 798 лежат ближе**. То есть собственный ре-релиз оказался дальше от позиции,
чем почти весь остальной Каталог.

Абрау-Дюрсо «Рислинг» 12% и 13% — светлая бутылка с белой этикеткой против зелёной с голубой,
расстояние 0,230, и **60 чужих Эталонов ближе**, в том числе вина Bakla Vines, «Нового Света»
и Domaine Lipko.

Следствие для пайплайна: **связь «slug ↔ внешний вид» не единственна во времени**.
Одна позиция Каталога может соответствовать нескольким физическим дизайнам, и Эталон
фиксирует только один из них. Для полки это означает регулярные промахи на редизайнах,
которые не чинятся ничем, кроме текстового канала и подсказки «похожие вина».

---

## 8. Класс C: визуально близкие вне общей серии

387 пар Эталонов с превью-RMSE < 0,06 не покрываются группировкой по серии — это соседние
линейки одного производителя с общим дизайном (Фанагория Cru Lermont, Château Le Grand Vostock
Reserve, Дербент Вино Ди Каспико, Агролайн Mountain Eagle).

Ключевое наблюдение: **среди них нет ни одной пары у разных виноделен**. Самая похожая
межвинодельческая пара Эталонов имеет RMSE 0,085 — почти на порядок дальше, чем ближайшие
внутривинодельческие (0,000–0,02). Практически это значит:

> Высокая визуальная близость — почти достоверный признак «та же винодельня».
> Ранжирование можно смело усиливать бонусом за совпадение винодельни, распознанной OCR:
> ложных срабатываний между производителями данные не показывают.

## 9. Класс D: одинаковые названия у разных виноделен

60 нормализованных названий встречаются у более чем одного производителя, покрывая
**362 позиции (17% Каталога)**: «Рислинг» — 38 позиций у 32 виноделен, «Пино Нуар» — 24 у 22,
«Каберне Совиньон» — 21 у 21, «Шардоне» — 20 у 18, «Совиньон Блан» — 20 у 19, «Мерло» — 19 у 19.

Это не визуальная, а текстовая ловушка: сортовое название само по себе не идентифицирует вино.
Позиция из этих 362 попадает в среднем в группу из 14 одноимённых карточек (медиана 11,
максимум 38), то есть матч по одному названию даёт около **17% шанса** угадать нужный slug.

## 10. Что из этого следует для решения

1. **Тай-брейк near-duplicates — текстовый, не визуальный.** CV-канал приносит группу
   кандидатов «одна серия одного производителя», внутри группы решает OCR: год, сорт, сахар,
   объём. Ранжирование по картинке внутри группы бессмысленно — разница 0,14% площади тонет
   в любом шуме съёмки.
2. **Кропать и распознавать этикетку в нативном разрешении.** Отдельный проход OCR по
   полосе «горлышко + этикетка» без ресайза под энкодер — единственный способ увидеть год,
   номер тиража и акцизную марку. Пайплайн «кроп бутылки → 384×384 → эмбеддинг» теряет их
   гарантированно.
3. **Атрибуты из slug — готовый словарь для сверки.** Сахар парсится у 1710 позиций,
   крепость у 1571, год — у части названий. Распознанный на этикетке год/сахар сверяется
   с этим словарём и переставляет кандидатов внутри группы.
4. **Группы класса A должны быть явно помечены в индексе.** 40 позиций с общим файлом —
   это встроенный потолок 50% top-1. Правильное поведение: не делать вид, что ответ
   уверенный, а показывать обе карточки («возможно, одно из двух»), это же ценится
   в сценарии «вина нет в Каталоге».
5. **Совпадение винодельни — сильный и безопасный сигнал.** Визуально близкие Эталоны
   у разных виноделен в данных отсутствуют; бонус за совпадение винодельни из OCR
   не создаёт новых ошибок.
6. **Редизайны не лечатся индексом.** Одна позиция может иметь несколько поколений дизайна,
   в Эталонах — одно. Это аргумент за то, чтобы «похожие вина» и отказ от ответа были
   полноценным сценарием выдачи, а не заглушкой.
7. **Привязку картинок строить от `Название фото`, а slug-канал оставить фолбэком.**
   Это бесплатно убирает две ложные группы неразличимости из трёх, не теряя ни одной
   позиции с картинкой (раздел 4).

## 12. Галерея: посмотреть глазами

`python3 scripts/collect_near_duplicates.py` раскладывает группы по папкам в
`data/near_duplicates/` (208 папок, 442 МБ, прогон ~5 мин):

```
data/near_duplicates/
  index.md                       все 499 групп таблицей, включая несобранные
  A-one-image-many-slugs/         20 папок — один файл на две позиции
  B-same-series/                  38 папок — серии, где есть хотя бы два Эталона
  C-visually-close/              150 папок — самые похожие пары вне серии
```

В каждой папке: `N_<slug>.png` — бутылки по отдельности (кроп по альфе, белый фон, 600 px),
`_compare.png` — все бутылки группы рядом, `_zoom.png` — крупный кроп именно той детали,
которая пару различает, `info.md` — поля Каталога по каждой позиции плюс метрики
(`relation`, доля различий, размеры и положение полос).

Папки отсортированы «самое похожее первым», так что смотреть стоит с начала каждого раздела.
Группы без единого Эталона (54 серии) и пары за пределами лимита `--max-visual-groups`
перечислены в `index.md`, но папок не имеют — смотреть там нечего.

## 13. Воспроизведение

```bash
python3 scripts/near_duplicates.py                 # текстовый отчёт (~2,5 мин)
python3 scripts/near_duplicates.py --json          # машинный формат
python3 scripts/near_duplicates.py --no-visual     # только текстовые группы, без Pillow/numpy
python3 scripts/collect_near_duplicates.py --force # разложить группы по data/near_duplicates/
```

Визуальная часть требует Pillow и numpy. Одного `PIP_CERT` мало: в окружении `SSL_CERT_FILE`
и `REQUESTS_CA_BUNDLE` указывают на недоступный корпоративный бандл, поэтому

```bash
SSL_CERT_FILE=/etc/ssl/cert.pem REQUESTS_CA_BUNDLE=/etc/ssl/cert.pem \
  python3 -m pip install --cert /etc/ssl/cert.pem numpy
```
