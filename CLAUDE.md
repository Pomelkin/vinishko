# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это за репозиторий

Хакатон-кейс РСХБ «Сканер российских вин» для платформы «Своё вино» (ТЗ целиком — `case.md`).
Кода пока нет: в репозитории только техническое задание, Каталог, Медиа-дамп, пакет для оценки
и утилиты анализа данных в `scripts/`. Git не инициализирован, `.venv` (Python 3.12) содержит
pip, Pillow и numpy. Ставить пакеты нужно с переопределением CA: переменные окружения
`SSL_CERT_FILE` и `REQUESTS_CA_BUNDLE` указывают на недоступный из песочницы корпоративный
бандл, поэтому одного `PIP_CERT` мало —
`SSL_CERT_FILE=/etc/ssl/cert.pem REQUESTS_CA_BUNDLE=/etc/ssl/cert.pem python3 -m pip install ...`.

Задача: по фотографии этикетки (снятой у полки, под углом, с бликами) вернуть **одну** карточку
вина из Каталога. CV-компонент обязателен, OCR — опционально. Целевая точность 90–100%,
SLA < 3 с. Вес критериев: достоверность выдачи 50/100, фича после поиска 20, архитектура 15,
дизайн 10, скорость 5.

Подробный разбор данных — `docs/DATA_RESEARCH.md`; все цифры оттуда воспроизводятся
`python3 scripts/analyze_data.py`. Отдельное исследование по похожим позициям —
`docs/NEAR_DUPLICATES.md` (`python3 scripts/near_duplicates.py`).

## Контракт со скриптом оценки (главное ограничение)

Скрипт кейсодержателя (`data/eval/participant_test.sh`) — единственный внешний интерфейс,
по которому считается основная оценка. Он жёстко задаёт форму API:

- `POST` на endpoint (по умолчанию `http://127.0.0.1:8080/v1/eval/predict`),
  изображение в multipart-поле **`image`**;
- ответ `200`/`201` с `{"slug":"..."}` либо `[{"slug":"..."}]` — другие формы `jq` не разберёт
  и `predicted_slug` станет `null`;
- `--connect-timeout 5`, `--max-time 10`: ответ дольше 10 с засчитывается как промах;
- запросы строго последовательные, без ретраев и параллелизма — прогрев моделей на первом
  запросе бьёт по latency всего прогона, инициализацию нужно делать на старте сервиса;
- скрипт падает (`die`), если выходной файл уже существует;
- `curl --form "image=@файл"` проставляет Content-Type по расширению, а файлы в `queries/`
  физически WebP при расширении `.jpg` — формат определять по сигнатуре, а не по заголовку
  и не по имени.

Запуск прогона:

```bash
cd data/eval && chmod +x participant_test.sh
./participant_test.sh \
  --images-dir ./queries \
  --manifest ./queries.tsv \
  --endpoint 'http://127.0.0.1:8080/v1/eval/predict' \
  --output ./predictions.jsonl
```

Целостность пакета оценки: `cd data/eval && shasum -a 256 -c checksums.sha256`.
Файлы из `data/eval/` менять нельзя — на Приватном eval-сете запускается та же версия скрипта.

## Данные

### Словарь наборов — называть только так

В кейсе пять разных наборов, путаница между ними даёт неверные выводы. В коде, документации
и обсуждениях использовать именно эти имена:

| Имя | Путь | Что это | Объём |
|---|---|---|---|
| **Каталог** | `data/strapi/strapi_output0709.csv` | карточки вин, первичный ключ — `Slug` | 4147 строк → 2103 позиции |
| **Медиа-дамп** | `data/strapi/img/` | сырой upload-каталог Strapi целиком | 2466 файлов, 1.2 ГБ |
| **Эталоны** | подмножество Медиа-дампа | рендеры бутылок, привязанные к позициям Каталога | 799 файлов → 766 позиций |
| **Хвост Медиа-дампа** | остальное в той же папке | контент сайта, к Каталогу не относится | 1667 файлов |
| **Публичный eval-сет** | `data/eval/queries/` + `data/eval/queries.tsv` | полевые фото для прогона | 3 фото |
| **Приватный eval-сет** | — | контрольные фото, у кейсодержателя | неизвестен |
| **Ключ ответов** | — | «query_id → правильный slug», у кейсодержателя | — |

Каталог и Эталоны — то, **среди чего** ищем (индекс). eval-сеты — то, **чем** ищем (запросы).

`data/near_duplicates/` — не исходные данные, а производный артефакт: галерея похожих позиций,
которую пересобирает `scripts/collect_near_duplicates.py`. Удалять и пересобирать безопасно.

**Обучающей выборки в пакете нет.** Эталоны — это индекс для retrieval: одна фотография на
позицию, и та у 36% Каталога. Меток нет ни у одного набора: для трёх фото Публичного eval-сета
не сказано, каким slug они соответствуют, — правильные ответы только в Ключе ответов
у кейсодержателя. Поэтому supervised-дообучение классификатора невозможно, а локальная
валидация строится только на синтетике из Эталонов и на собственной размеченной съёмке.

### Каталог — `data/strapi/strapi_output0709.csv`

Колонки: `Название вина, Категория, Цвет, Регион, Сорт винограда, Описание, Винодельня, Slug,
Название фото`. Описания многострочные (406 позиций) — читать только настоящим CSV-парсером,
не `split(',')`.

- 4147 строк, **2103 уникальных slug**: 2044 позиции задублированы ровно дважды, 59 идут одной
  строкой (похоже на draft + published). Дубли байт-идентичны, противоречий по полям нет —
  дедупликация «первая строка на slug» безопасна и обязательна.
- `Категория` — это **цвет вина** (Белое 999 / Красное 795 / Розовое 293 / Оранжевое 16),
  а `Цвет` — свободный текст органолептики (826 значений). Путать нельзя.
- Отдельных полей **нет** для: года урожая, объёма, крепости, сахара, типа (тихое/игристое),
  цены, рейтинга Роскачества, URL. Часть восстанавливается из структурированного slug
  (`<винодельня>-<название>-<сорт>-<цвет>-<сахар>-<крепость×10>`): числовой суффикс крепости
  у 75% позиций, сахар — у 1710 из 2103. Рейтинга Роскачества в данных нет вообще.
- Near-duplicates: 60 названий встречаются у разных виноделен (362 позиции, «Рислинг» — 38),
  92 группы «одна серия одного производителя» покрывают 202 позиции, 20 групп (40 позиций)
  делят один и тот же файл-Эталон. Разбор целиком — `docs/NEAR_DUPLICATES.md`. Главное:
  позиции с собственными Эталонами различаются **всегда**, но различие бывает размером
  0,14% площади бутылки (год «2017» против «2021» — 12×55 px при ширине бутылки 640 px),
  то есть недоступно глобальному эмбеддингу и требует OCR по кропу этикетки.
  31 название с висячими пробелами — нормализовать.

### Медиа-дамп — `data/strapi/img/` (1.2 ГБ, 2466 файлов)

Не «каталог фотографий», а сырой Strapi-upload всего сайта: 799 файлов — Эталоны,
остальные 1667 — Хвост: фото событий и производств, логотипы, `.geojson` регионов,
иллюстрации блога, генеративные картинки (209 файлов вида `generated_image_…`,
`Chat_GPT_Image_…`) и 1065 файлов с хеш-именами без внятного содержания. Плюс 157
байт-идентичных копий. Расширения: 2398 `.webp`, остальное jpg/png/heic/jfif/svg/geojson/xml,
причём расширение не гарантирует содержимое. В Хвосте 67 файлов имеют геометрию бутылки —
там есть настоящие рендеры под неинформативными именами, но вперемешку с clip-art и повторами
уже покрытых позиций; резерв на десятки позиций, привязывать вручную или по OCR.

Эталоны — студийные рендеры **бутылки целиком на прозрачном фоне** (753 из 799 в RGBA),
аспект w/h p50 = 0.29, ширина самой бутылки p50 = 310 px, у 62% — уже 400 px. Этикетка на
медианном Эталоне ≈ 310×300 px: энкодеру хватает, для OCR мелкого шрифта — нет.

**Имена файлов в `img/` уже приведены к `Название фото` из Каталога** — связывание прямое,
обычным lookup по имени: 763 позиции матчатся точно, ещё 3 — по «имя файла ≈ slug».
Разбивка файлов: 784 переименованы скриптом, 1682 сохранили исходные Strapi-имена
`<slug_имени>_<10 hex>.<ext>`; из этих 1682 к Каталогу относятся только 15, остальные
1667 — Хвост. Добирать покрытие fuzzy-матчем по именам бесполезно: агрессивная нормализация
и difflib ≥ 0.86 дают **ровно 0** новых позиций.

**Итог: Эталон есть у 766 позиций Каталога из 2103 (36.4%); у 1337 позиций изображения
в Медиа-дампе просто нет.** Дыра кластеризована: 75 из 135 виноделен без единого Эталона
(Мысхако 92 позиции, Кубань-Вино 87, Союз-Вино 69, Шато Пино 49, Ведерниковъ 43), 80% пробела
закрывают 44 винодельни; по регионам покрытие от 86% (Дагестан) до 0% (Нижняя Волга,
Северная Осетия). Отдельно: 22 байт-идентичных Эталона обслуживают по 2 slug каждый — это
20 групп и 40 позиций (две пары продублированы лишними копиями файла), и для них top-1
по картинке недостижим, нужен текстовый тай-брейк.

Покрытие Каталога Эталонами — жёсткий потолок F1 по CV-каналу. Поэтому текстовый канал
(OCR запроса → fuzzy по `Винодельня` + `Название вина` + `Сорт`) нужен не «для усиления»,
а как единственный способ достать 64% Каталога.

### Публичный eval-сет — `data/eval/queries/` + `data/eval/queries.tsv`

Манифест `queries.tsv` (`query_id<TAB>image_path`, 3 строки) + `queries/` с 3 полевыми фото
3024×4032. **Все три файла физически WebP** независимо от расширения — определять формат
по содержимому.

Публичный eval-сет не годится для измерения качества: **ни у одного из трёх запросов нет
Эталона**, а два из трёх вин вообще отсутствуют в Каталоге (Табия Пино Нуар 2025 — нет позиции;
Aristov Donum XXIV — нет позиции; Массандра Мускатель белый есть позицией
`massandra-muskatel-belyy-belye-sorta-vinograda-beloe-sladkoe-16`, но без Эталона). На двух
фото из трёх в кадре несколько бутылок, причём на `q-000001` соседняя бутылка в Каталоге есть,
а целевая — нет. Годится только для smoke-теста контракта и замера latency.

## Рекомендуемый стек из ТЗ

Nuxt (бэкенд+фронт), PostgreSQL + pgvector, SigLIP 2 как CV-бэкбон, Strapi CMS, Docker.
Стек рекомендательный, но совпадение с целевой платформой учитывается в оценке архитектуры.
Деплой не требуется — демо локальное, GPU свой или внешние API.

При появлении кода ТЗ ждёт в репозитории `README.md` (сетап, запуск, переменные окружения,
ограничения) и `ARCHITECTURE.md` с разделением слоёв: нормализация фото → извлечение
признаков → поиск по Каталогу → выдача карточки → фича после поиска.

## Что помнить при реализации

- Кроме eval-эндпоинта нужен «продуктовый» API, отдающий полную карточку и confidence
  (F1 top-1 и top-5) — в UI метрики выводить не нужно, но в ответе API они должны быть.
- Подсказка кейсодержателя: нормализация фотографии (кроп бутылки/этикетки, выравнивание,
  борьба с бликами) даёт заметный прирост F1 — это дешевле, чем дообучение модели.
  Геометрия данных это подтверждает: на Эталоне этикетка — малая часть кадра, на запросе —
  половина, поэтому кропать и выравнивать надо обе стороны сравнения.
- Сценарий «вина нет в Каталоге» обрабатывается отдельно: похожие вина / аналоги других
  виноделен ценятся выше, чем честное «не найдено». При покрытии 36% это не краевой случай,
  а регулярный режим работы.
- В кадре у полки почти всегда несколько бутылок — выбор целевой (центральная / максимальная
  по площади) должен быть явным шагом пайплайна, иначе сервис уверенно ответит про соседа.
- Позиции без Эталона обязаны остаться в индексе: их ловит только текстовый канал.
  Near-duplicates разводятся не картинкой, а годом/сахаром/сортом из OCR против атрибутов,
  распарсенных из slug. Важно: год на этикетке исчезает при ресайзе бутылки под вход
  энкодера — читать его нужно по кропу этикетки в нативном разрешении
  (обоснование и цифры — `docs/NEAR_DUPLICATES.md`).
- Интерфейс mobile-first, в стилистике портала «Своё Вино».

## Инструменты в `scripts/`

- `analyze_data.py` — сводная статистика по Каталогу, Медиа-дампу и их связыванию
  (`--json` для машинного формата). Источник всех цифр в `docs/DATA_RESEARCH.md`;
  запускать после любой замены дампа.
- `near_duplicates.py` — разбор похожих позиций: текстовые группы (серия, коллизии названий),
  группы «один Эталон на несколько slug» и попиксельное сравнение Эталонов с локализацией
  различающей детали. Источник цифр в `docs/NEAR_DUPLICATES.md`. Полный прогон ~2,5 мин,
  `--no-visual` считает только текстовую часть, `--json` — машинный формат.
- `collect_near_duplicates.py` — раскладывает группы near-duplicates по папкам
  `data/near_duplicates/<класс>/<группа>/` с картинками, коллажем, зумом различающей детали
  и `info.md`. Берёт группировку из `near_duplicates.py`. Прогон ~5 мин, ~440 МБ,
  перезапись только с `--force`.
- `rename_img_to_csv_names.py` — переименование файлов `img/` в имена из CSV по
  реконструированному правилу Strapi (`nameToSlug` = `@sindresorhus/slugify` с
  `separator="_"`, `lowercase=false`). **Уже применено** к 784 файлам, журнал —
  `rename_journal.json`, откат — `--revert`. Анализ инвариантен к этому состоянию;
  повторный запуск нужен только после замены дампа.

## Открытые вопросы к кейсодержателю

Блокируют оценку достижимого потолка, задать до основной реализации:

1. Полный ли Медиа-дамп? Для 1337 из 2103 позиций Каталога Эталона нет — это дефект выгрузки?
2. Приватный eval-сет снят по всему Каталогу или только по позициям, у которых есть Эталон?
3. Каталог на контрольном прогоне тот же, что в `strapi_output0709.csv`, или свежее?
   Два из трёх запросов Публичного eval-сета не имеют карточки в выданном Каталоге.
4. Как засчитывается ответ, если вина в Каталоге нет — промах при любом ответе или есть
   ожидаемый slug/пустой ответ?
5. Какая бутылка считается целевой, если в кадре несколько?
